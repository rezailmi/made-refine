## Maintainer decisions from the grill session (2026-06-12)

These are binding on executors; the plan files already reflect them:

- **006 direction**: reattach + reapply pending styles on a *unique, high-confidence* locator match after a remount; otherwise mark the edit stale (visible, still sendable with cached locator). Never guess. Aggressive reattachment rejected.
- **001**: both guards confirmed — `editModeActive` AND `isInputFocused()` (Cmd+Z does native field undo while a panel input is focused, Figma-style). Tests that encode the old behavior get updated, not the guards removed.
- **002**: extended beyond TODOS.md's inline-only fix — when no inline transform exists, snapshot `getComputedStyle(el).transform` at drag start and compose against the matrix (covers Tailwind class transforms, the dominant real-world case). Restore stays inline-only.
- **003**: gate polarity is **development-only injection** (`!api.env('development')` → no-op), not merely a production skip — keeps attributes out of consumers' test snapshots too.
- **004**: pure-lazy rebuild confirmed safe — verified the hover path (`interaction-overlay.tsx` → `computeHoverHighlight`) does no fiber lookups; lookups happen at selection/send frequency.
- **007**: full scope chosen — persistent error with reason on footer + toolbar, AND per-item `Failed` badges in the edits popover after partial batch failures. Audit correction recorded: 2s-flash feedback already existed; failed edits were never lost.

## Direction findings (maintainer options, not ranked against bugs)

- **Richer agent payload**: `getComponentProps` already extracts authored props (`react-fiber.ts:184+`) and `collectSubElementSources` only reads `data-direct-edit-source` DOM attributes (`utils.ts:2334+`) — walking child fibers would give per-child source files without the vite/babel plugin. Evidence the payload matters: the agent-prompt tuning commits (`3d17986 Update agent prompt to ask for variable/token mapping`).
- **Locator re-capture at send time + multi-candidate selectors**: `buildDomSelector` (utils.ts:2042) already has a good fallback chain (id → stable attrs → nth-of-type) but emits a single selector string captured at selection time; sending an ordered candidate list and refreshing at send would raise agent hit rate on dynamic UIs. Partially superseded by 006 (stale/reattach design covers locator freshness).

## Findings considered and rejected

So nobody re-audits these:

- **"No selector fallback chain"** (audit subagent claim) — wrong; `buildDomSelector` (`src/utils.ts:2042–2077`) already tries unique id → `data-testid`/`data-qa`/`data-cy`/`aria-label`/`role` → class-qualified nth-of-type path.
- **"Selection overlay rect goes stale on scroll/resize"** — covered; `selection-overlay.tsx` uses `useViewportEvents` + a MutationObserver + a layout effect. Residual gap (CSS-animation-driven transforms with no DOM mutation) is an edge case, not worth a polling loop.
- **"Keyboard listener race on remount"** — the two effects in `use-keyboard-shortcuts.ts` are standard add/remove pairs with correct cleanup; no bug.
- **"getGroupBounds crashes on empty array"** — `multi-selection-overlay.tsx:28–43` returns a zero rect and renders an invisible div; safe. (A test would still be nice — backlog #2.)
- **"No CI"** — wrong; `publish.yml` runs `tsc --noEmit` + `vitest run` on push and PR to main. Only lint is missing (backlog #4).
- **"Send failure silently loses user work / no feedback"** — doubly overstated; failed sends keep the edit in the session map AND both send buttons already flash a red-X failure state for 2s. The genuine residual gaps (persistence, reason, per-item attribution) became plan 007.
- **Drag AbortController missing `pagehide` cleanup** (`use-canvas.ts:623–644`) — theoretical edge (tab close mid-drag); not worth a plan.
- **CLI path traversal** — `findFile` candidates are hardcoded by the CLI, not user input; harden only if a user-config mode is ever added.
